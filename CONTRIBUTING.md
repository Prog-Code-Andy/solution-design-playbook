# Contributing

Keep the playbook model-independent and keep project-specific facts out of reusable templates.

1. Open a proposal describing the problem and affected artifacts.
2. Use a new EDR when changing a durable governance or architecture decision.
3. Preserve existing identifiers and avoid renumbering published prompts.
4. Update examples when a schema or workflow changes.
5. Validate Markdown links, YAML syntax, prompt prerequisites, and approval stops.
6. Never include secrets, private requirements, or production evidence in this repository.
