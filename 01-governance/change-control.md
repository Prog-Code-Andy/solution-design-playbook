# Change Control

Classify a proposed change before editing approved artifacts.

| Change | Required control |
|---|---|
| Durable architecture, security, privacy, data, process, or operational decision | New EDR that amends or supersedes the earlier decision |
| Exact interface or schema change | New contract version and, when policy changes, an EDR |
| Technical detail within accepted boundaries | New design version |
| Future delivery order or scope change | Roadmap revision and approval |
| Not-started phase boundary change | Phase revision and approval |
| Small local defect | Issue/task plus targeted verification |
| Systemic defect or accepted-requirement gap in completed work | REM package |
| New functionality disguised as repair | New or revised roadmap/phase, not REM |

Preserve evidence and prior approved versions.
